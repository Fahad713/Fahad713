## 🏫 GCC-SmartHub

### AI-Powered Academic & College Management System

**GCC-SmartHub** is my **Final Year Project**, developed specifically for **Government Graduate College of Commerce**.

It is a full-stack academic management system designed to cover major college operations including:

* Academic management
* Accounts management
* Library management
* Security management
* Student management
* Attendance
* Examinations and results
* Fee management
* Timetable management
* Notifications
* AI-powered features

**Technology Stack**

`ASP.NET Core Web API` · `Entity Framework Core` · `SQL Server` · `React` · `TypeScript` · `Redux Toolkit` · `React Native` · `JWT`

### Key Engineering Work

* Implemented **Clean Architecture** for the backend
* Developed RESTful APIs for multiple enterprise modules
* Implemented **JWT authentication and role-based authorization**
* Designed complex academic and administrative workflows
* Built automated admission processes
* Integrated AI-powered functionality into the system

### Most Challenging Components

**Automated Admission Module**

The admission module is one of the largest modules in the system and was designed to automate the admission workflow.

It includes functionality such as:

* Automatic challan generation
* Merit list generation
* Class generation
* Admission processing
* Automated workflow handling

**AI-Powered Timetable Generation**

Another technically challenging component is the AI-powered timetable generation system.

The solution uses a **.NET ML model together with the Google CP-SAT solver** to generate timetables while considering multiple academic constraints.

The main challenge was not simply generating a timetable, but determining **which data and constraints should influence the scheduling process and which should not**, while attempting to avoid lecture conflicts and produce a workable academic schedule.

## 💼 SkillHire

### Job & Freelancing Platform

**SkillHire** is a full-stack platform that combines **job management and freelancing workflows** into a single system.

The platform supports two sides of the marketplace:

* **Employers / Job Providers**
* **Skill Providers / Freelancers**

I designed and developed the complete project myself, including the backend, frontend, business logic, authentication, and workflow validation.

**Technology Stack**

`ASP.NET Core Web API` · `Entity Framework Core` · `SQL Server` · `React` · `JWT` · `Role-Based Authorization`

### Key Engineering Work

* Developed the complete application architecture
* Designed employer and freelancer workflows
* Implemented authentication and authorization
* Built job posting and application workflows
* Designed complex business rules and validations
* Integrated AI-powered functionality for job matching and application automation

### Most Challenging Component

The most challenging part was designing the system around users who can participate in different workflows while maintaining valid business rules.

For example, the system needs to consider scenarios such as whether a user who has already been hired by a company should be allowed to apply for another position within the same company.

Designing and validating these scenarios required careful consideration of user states, company relationships, job applications, hiring status, and business rules.

This project significantly improved my ability to think about **real-world edge cases and business logic rather than just implementing CRUD operations**.

## 🏭 Factory ERP Mobile Application

### Offline-First Manufacturing & Business ERP

Factory ERP is a mobile-based ERP system covering manufacturing, inventory, accounting, and business operations.

I developed the **complete project myself**.

**Technology Stack**

`SQLite` · `Google Sheets API` · `Offline-First Architecture` · `FIFO Costing` · `Synchronization Engine`

### Key Features

* Production management
* Purchasing
* Sales management
* Inventory management
* Expense management
* Stock adjustment
* FIFO inventory costing
* COGS calculation
* Customer and supplier ledgers
* Offline-first operation
* Multi-user synchronization
* Conflict resolution
* Stock reconciliation

### Most Challenging Component

The most challenging part of this system was designing synchronization around **Google Sheets as the central storage system**, rather than using a traditional cloud backend such as AWS.

The application needed to reliably:

* Store data locally
* Synchronize changes
* Fetch updated data
* Maintain consistency across users
* Handle synchronization conflicts
* Reconcile stock data

This project gave me practical experience with **offline-first architecture, synchronization strategies, centralized data storage, and distributed data consistency**.
